# Level Design

Документ каждого уровня — `.gameforge/levels/<id>.md` (шаблон `templates/level.md`). Уровень строится итерациями: **бумага → greybox → плейтест → арт-пасс → полировка**. Арт не трогаем, пока greybox не прошёл плейтест.

## 1. Метрики (один раз на проект, раздел в gdd.md)

Прежде чем строить — зафиксируй цифры из реального контроллера в движке (измерь, не угадывай): высота и длина прыжка, скорость бега, рост персонажа, ширина прохода, высота укрытия, дальность оружия/способности, радиус камеры. Из них — «кит» стандартных размеров: проход = 2–3× ширины персонажа, двери, ступени, укрытия, промежутки «легко / сложно / невозможно перепрыгнуть». Сохрани как данные (ScriptableObject / Resource / DataAsset) и как префабы/сцены-кирпичики.

## 2. Бумага

- **Цель уровня**: что игрок учит или проверяет (новая механика? комбинация? экзамен?).
- **Бит-чарт**: последовательность битов (обучение → практика → твист → кульминация → отдых) с интенсивностью 1–5 и примерным временем. Чередуй напряжение и отдых.
- **Критический путь** и опциональные ветки (секреты, награды), ориентиры (landmarks) видны издалека, «хлебные крошки» светом/цветом.
- **Схема**: ASCII-план или список зон с переходами. Для процедурных уровней — правила генерации и инварианты (всегда есть путь к выходу, сложность растёт).

## 3. Greybox по движку

| Движок | Инструмент | Как |
|--------|------------|-----|
| Unity | ProBuilder, Splines, префабы-кирпичики из кита | через `unity command` / `script eval` (создание объектов, расстановка), не правкой .unity руками |
| Godot | CSG-ноды, GridMap (3D), TileMapLayer (2D) | MCP (`create_scene`, `add_node`) или `@tool`-скрипт генерации |
| Unreal | Modeling Mode, BSP/Geometry Script, PCG для больших пространств | Python в редакторе / MCP |
| Любой | Blender (gameforge:blender) — блокаут и модульный кит | экспорт в движок |

Цвета greybox: проходимое — серое, интерактив — жёлтое, опасность — красное, цель — зелёное. Одинаково на всех уровнях.

## 4. Проверка (агент делает сам)

- **Проходимость**: запечь NavMesh/навигацию и проверить, что путь старт → выход существует; все обязательные предметы достижимы. Unity — `unity:initialize-ai-navigation`.
- **Soft-lock**: нет мест, откуда нельзя выбраться (ямы без выхода, двери, закрывающиеся за спиной без ключа, ресурс, без которого не пройти и который можно потратить).
- **Время прохождения**: бот или ручной прогон по критическому пути, сравни с бит-чартом.
- **Скриншоты сверху и с точки зрения игрока** в ключевых битах.
- **Производительность**: draw calls и FPS в самой тяжёлой точке уровня, окклюзия.

## 5. Плейтест уровня

Через gameforge:playtest: где игрок заблудился, где умер больше 3 раз, где заскучал (долго без события), что пропустил. Правки → снова greybox. Только потом арт-пасс (gameforge:blender для моделей, модульные киты, декали, свет) и звуковой пасс (gameforge:audio — эмбиент-зоны, триггеры).

## 6. Прогрессия уровней

Таблица в gdd.md: уровень → новая механика / комбинация → сложность 1–10 → время. Кривая «пила»: сложность растёт, после пика — короткий лёгкий уровень. Новая механика вводится в безопасном месте, затем проверяется под давлением.
