# Project Memory — чтобы не забывать, что это за проект

Память проекта живёт **в файлах проекта**, а не в разговоре. Разговор сжимается и заканчивается, файлы — нет.

| Файл | Что хранит | Как меняется |
|------|-----------|--------------|
| `.gameforge/context.md` | паспорт: что за игра, столпы, где мы, ключевые решения, глоссарий, карта проекта, соглашения, предпочтения пользователя | **переписывается**, держим ≤ 150 строк и актуальным |
| `.gameforge/history.md` | журнал: что сделано, решено, проверено в каждой сессии | **только дописывается в конец** |
| `.gameforge/gdd.md` | дизайн игры | правится + строка в «Истории изменений» + версия |
| `.gameforge/state.md` | этап, ворота, следующий шаг (машиночитаемо) | правится |
| `.gameforge/decisions/ADR-*.md` | крупные технические решения | новый файл на решение |

Как это попадает в контекст автоматически:
- хук SessionStart (`scripts/status.sh`) на старте, resume, `/clear` и **после сжатия контекста** выводит context.md, этап и последние записи истории;
- в `CLAUDE.md` проекта стоит импорт `@.gameforge/context.md` (добавляет gameforge:setup);
- хук Stop (`scripts/history-check.sh`) напоминает дописать history.md, если файлы проекта менялись, а журнал давно не обновлялся.

## 1. Начало работы (восстановление контекста)

1. Если контекст из хука уже есть — не перечитывай файлы зря; опирайся на него.
2. Если нет (хук не сработал, другой клиент) — прочитай `context.md`, хвост `history.md` (последние 3–5 записей), `state.md`.
3. Нужен дизайн — читай конкретный раздел `gdd.md`, а не весь документ.
4. Если `context.md` противоречит коду или пользователю — **код и пользователь правы**, исправь context.md и запиши это в history.

На вопрос «что это за проект / на чём остановились» отвечай из этих файлов, кратко: игра в одной фразе, этап, последняя работа, следующий шаг.

## 2. Когда обновлять

| Событие | Что обновить |
|---------|--------------|
| Закончен кусок работы (задача, фича, ассет, уровень) | запись в history.md |
| Принято решение (механика, архитектура, scope, отказ от чего-то) | history.md + context.md → «Ключевые решения» (+ ADR, если крупное техническое) |
| Изменилась механика, баланс, scope, контент | gdd.md + строка в «Истории изменений» + версия; если затронуты столпы/core loop — и context.md |
| Новое имя персонажа, локации, механики, ресурса | context.md → «Глоссарий» (как в игре и как в коде) |
| Пользователь сказал о своих предпочтениях («не люблю X», «всегда делай Y») | context.md → «Предпочтения пользователя» |
| Сменился этап или milestone | state.md + context.md → «Где мы сейчас» + **снимок GDD** (см. 4) |
| Конец сессии / перед долгой паузой | history.md: что сделано, что не проверено, следующий шаг |

Не жди конца сессии, если сделано много — контекст может сжаться раньше. Обновляй по ходу.

## 3. Как писать

**history.md** — запись в конец файла по формату из шапки шаблона:
```markdown
## 2026-11-26 18:40 — Прыжок и coyote time
- Сделано: P-03, P-04 — PlayerController.cs, JumpSettings.asset
- Решено: coyote time 0.12 с вместо 0.2 — 0.2 ощущалось как «полёт»
- Проверено: EditMode тесты 14/14, playmode-скрин / НЕ проверено: геймпад
- Проблемы: —
- Дальше: P-05 двойной прыжок
```
Факты, а не пересказ разговора. Не дублируй код и диффы — достаточно путей и ID задач.

**context.md** — состояние «на сейчас», не история. Устаревшее удаляй или переноси суть в history. Если файл перевалил за 150 строк — сожми: подробности в GDD/ADR, здесь ссылка.

**Ротация history.md:** длиннее ~500 строк → старые записи в `.gameforge/archive/history-<год>.md`, в начало history.md — сводка из 10–15 строк о перенесённом периоде.

## 4. Версии GDD

- В шапке GDD: `Версия` и `Обновлён`. Минорная версия +0.1 — правка механики, баланса или scope; мажорная — смена этапа или пересборка концепта.
- Каждое изменение — строка в «Истории изменений» (новые сверху): версия, дата, раздел, что, почему.
- **Снимок** при закрытии milestone, смене этапа или перед крупной переделкой: копия в `.gameforge/archive/gdd-v<версия>-<YYYY-MM-DD>.md`.
- Если проект под git — коммить `.gameforge/` вместе с кодом (не добавляй его в .gitignore). Это и есть полная история документа.

## 5. Чего не хранить

Ключи, пароли, токены, личные данные — никогда, ни в одном из этих файлов. Временные рассуждения и черновики — в history только вывод.
