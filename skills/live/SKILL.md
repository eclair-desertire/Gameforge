# Live — после релиза

## 1. Данные

- **mobile:** если установлен — `game-trend-skills:tracking-game-metrics` (он знает пороги D1/D7/CPI для жанров). Источник цифр — пользователь (скрин/CSV из консоли стора, аналитики, рекламной сети). Для сбора своих событий в Unity — Unity Analytics / `unity:build-live-game`.
- **pc:** Steamworks → вишлисты, конверсия вишлист→покупка, возвраты (> 10% — тревога), медиана игрового времени, отзывы (группируй жалобы по темам), регионы.

Цифры и выводы — в `.gameforge/releases/<version>-metrics.md` с датой.

## 2. Решение

| Сигнал | Действие |
|--------|----------|
| Метрики выше порогов жанра | scale: больше контента, UA (mobile), обновления + скидки/фестивали (pc) |
| Близко к порогам, понятная причина | iterate: 1–3 гипотезы, каждая как задача в backlog с ожидаемым эффектом на метрику |
| Сильно ниже и нет гипотез | sunset: заморозить, забрать выученное в следующий концепт |

Решение принимает пользователь; ты даёшь рекомендацию с цифрами. Запиши в журнал `state.md`.

## 3. Апдейты

Новый цикл: гипотеза → gameforge:plan (milestone «Update X.Y») → build → playtest → release. Для live-фич (ивенты, боевой пропуск, лидерборды, remote config) в Unity — `unity:build-live-game`.

## 4. Ретроспектива

Раз в milestone/релиз — 5 строк в `state.md` → «Журнал решений»: что сработало, что нет, что переносим в следующий проект. Это и есть твоя накопленная студийная экспертиза.
