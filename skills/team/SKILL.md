# Команда GameForge

Основная сессия — **руководитель студии**: говорит с пользователем, решает, кому отдать работу, собирает результаты и проверяет их. Агенты не видят разговора и **не могут задать вопрос пользователю** — всё нужное передаётся в брифе.

## 1. Состав

Модель указана в файле агента (`agents/*.md`) и применяется при каждом вызове; при необходимости её переопределяет параметр `model` в вызове.

### Помощники (haiku)
`scout` — найти и прочитать (код, логи, доки, веб, тренды), ничего не меняет. `runner` — выполнить готовые команды (сборки, тесты, ffmpeg, пакетный экспорт) и коротко доложить.

## 2. Кто что делает — маршрутизация

1. **Механическое и точно описанное** → `scout` / `runner`.
2. **Задача из backlog с критерием «готово, когда»** → специалист своего направления.
3. **Решение внутри направления** (стандарт, стиль, баланс) → лид.
4. **Решение через несколько направлений или против столпов** → директор (дизайн — creative-director, техника — technical-director, скоуп и сроки — producer).
5. **Воля пользователя** (вкус, деньги, покупки, публикация, отказ от фичи) → только основная сессия спрашивает пользователя.

Не вызывай агента ради 1–3 вызовов инструментов, которые проще сделать самому: бриф обойдётся дороже работы.

## 3. Правила команды

- **Вертикально:** директор → лид → специалист. Сложное решение не перепрыгивает уровень; простое исполнение не поднимается наверх.
- **Горизонтально:** коллеги одного уровня консультируют друг друга, но не решают за чужое направление.
- **Владение файлами:** каждый правит только свою зону (раздел 6). Чужая зона — только по явному поручению в брифе.
- **Конфликт** → общему руководителю; нет общего — creative-director (дизайн и опыт игрока) или technical-director (техника). Финал за пользователем, если затронуты столпы, скоуп или деньги.
- **Изменение, задевающее несколько направлений** (новая механика меняет UI, звук, баланс) — producer раскладывает последствия в backlog.
- **Инструменты:** перед работой с внешней программой агент запускает `check-tools.py --task …`. Не готово — возвращает BLOCKED со списком; устанавливает только основная сессия через gameforge:doctor и с согласия пользователя.
- **Отчёт — не доказательство:** основная сессия проверяет результат сама (diff, тест, файл, превью) до того, как отметить задачу.

## 4. Бриф агенту (шаблон)

```
Проект: <абсолютный путь>, движок <Unity 6000.x / Godot 4.x / UE 5.x>, трек <mobile/pc>.
Плагин GameForge: <путь к плагину> (скрипты: scripts/check-tools.py).
Задача: <ID из backlog и формулировка>. Готово, когда: <проверяемый критерий>.
Контекст: читай <файлы и разделы по заголовкам — не целиком>; решения, которые уже приняты: <…>.
Твоя зона: <файлы/папки>. Не трогай: <…>.
Инструменты: <MCP/CLI, проверены doctor'ом: да/нет>.
Верни: блок отчёта (раздел 5).
```

## 5. Формат отчёта агента (последний блок ответа)

```
СТАТУС: DONE | DONE_WITH_NOTES | NEEDS_DECISION | BLOCKED
ФАЙЛЫ: <изменённые/созданные>
ПРОВЕРЕНО: <чем и как>
НЕ ПРОВЕРЕНО: <честно>
РЕШИТЬ ПОЛЬЗОВАТЕЛЮ: <варианты, если NEEDS_DECISION>
ДАЛЬШЕ: <следующий шаг или кому передать>
```
Ревьюер (директор/лид) отвечает вердиктом: **APPROVE** · **APPROVE_WITH_NOTES** (мелочи, можно идти дальше) · **REVISE** (конкретный список правок) · **BLOCK** (почему и что нужно решить). Вердикт и причина — строкой в «Журнал решений» `state.md`.

|----|-------|-----|-----------|

| TD-TECH | перед prototype | technical-director | движок, архитектура, главные тех-риски, бюджеты платформы |

| AD-STYLE | перед массовым производством арта | art-director | арт-библия, палитра, свет, масштаб, тестовые ассеты |

| LP-REVIEW | каждая задача `[code]` перед `[x]` | lead-programmer | архитектура, стандарты, тесты, без регрессий |

| CD-STAGE / TD-STAGE | смена этапа (studio) | оба директора | ворота этапа выполнены по существу |
| QL-RELEASE | перед публикацией | qa-lead (+ build-engineer) | чеклист релиза, сборки на целевых платформах |

## 8. Режим строгости — `review:` в `state.md`

Два режима, ревью командой есть всегда. Пустое или неизвестное значение — считай `lean`.

| Режим | Что запускается | Когда |
|-------|-----------------|-------|
| `lean` (по умолчанию) | ворота этапов (CD/TD/PR/QL) и AD-STYLE всегда; LP-REVIEW и AD-ASSET — для задач с пометкой `review` и сводно на закрытии milestone | обычная работа |
| `full` | все ворота на каждой задаче | PC-проект, большой скоуп, релиз близко, после болезненных регрессий |

## 9. Сценарии командной работы

Независимые шаги запускай параллельно (все вызовы `Agent` сразу), зависимые — по очереди. Если кто-то вернул BLOCKED — сразу сообщи пользователю, остальное доведи и дай частичный отчёт.

- **Новая фича:** game-designer (механика в GDD) → [параллельно: economy-designer — числа · ux-designer — флоу] → producer (задачи в backlog по потокам) → [параллельно: gameplay-programmer · ui-programmer · audio-designer · 2d/3d-artist] → lead-programmer (LP-REVIEW) + art-director (AD-ASSET) → qa-playtester → основная сессия показывает пользователю.
- **Арт-ассет / партия:** art-director (бриф по арт-библии) → 2d-/3d-artist (с превью) → art-director (AD-ASSET) → tech-artist (импорт, материалы, бюджеты) → qa-playtester (в игре).
- **Уровень:** level-designer (документ + greybox) → qa-playtester (проходимость) → game-designer (пейсинг) → art-director + 3d-artist (арт-пасс) → tech-artist (производительность).
- **Звук и музыка:** audio-director (направление) → [параллельно: audio-designer — SFX · composer — музыка] → audio-director (микс в игре).
- **Концепт:** scout ×N параллельно (сигналы трендов) → основная сессия (идеи) → game-designer (концепт) → creative-director (вердикт) + technical-director (TD-TECH) + producer (оценка скоупа).
- **Релиз:** qa-lead (план приёмки) → [параллельно: build-engineer — сборки · qa-playtester — регресс · marketing-lead — страница и материалы] → qa-lead (QL-RELEASE) → пользователь даёт «да» на публикацию.
- **Сложный баг:** scout (логи, воспроизведение) → движковый специалист или gameplay-programmer (фикс) → lead-programmer (ревью) → runner (тесты).
